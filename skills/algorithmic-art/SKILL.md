# Algorithmic Art

Generative art is a system that makes images. The artistic decisions live in the rules and parameters, and good work comes from a clear idea, a small number of well-chosen rules, and many iterations of looking at outputs.

## When to use

- Generative posters, backgrounds, patterns, covers, visual identities, interactive sketches.
- Turning data or text into abstract visuals.
- Static compositions drawn by code (canvas or SVG) rather than generated by an image model.

## Gather first

1. Purpose and output: wallpaper, print (needs physical size and DPI), web background, interactive piece, animation.
2. Mood and constraints: palette, brand colours, density, light or dark.
3. Medium: p5.js for quick sketching and interactivity; plain canvas 2D for no dependencies; SVG for crisp vector output and plotters; WebGL shaders for heavy per-pixel work.
4. Whether the user wants one piece, a series, or a tool they can tune.

## Procedure

### 1. Concept
State the idea in a sentence: a process, not an image ("particles follow a slowly changing flow field and leave faint trails", "a grid of tiles where each tile's rotation depends on distance from a few attractors"). The process decides the character of the result.

### 2. Determinism first
- Use a seeded random number generator (p5's `randomSeed` and `noiseSeed`, or a small seeded PRNG such as mulberry32 in plain JS). Never mix in unseeded `Math.random`.
- Read the seed from the URL or a parameter, and show it on screen or in the filename so any output can be recreated.

### 3. Parameters
Expose the few values that matter (count, scale, noise frequency, palette index, stroke weight, iterations) in one config object. Add simple controls (sliders, or keyboard shortcuts for new seed and save) if the user wants to explore. Keep ranges sensible so most seeds look good.

### 4. Building blocks to draw from
- Noise fields (Perlin/simplex) for organic flow, terrain and texture.
- Subdivision and recursion (quadtrees, L-systems, recursive rectangles).
- Particle systems and agents with simple rules.
- Grids and tilings with per-cell variation.
- Circle packing, Poisson-disc sampling for even spacing.
- Geometry: polar coordinates, Lissajous curves, superformula.
- Layering with transparency and blend modes for depth.

Combine two or three, not ten.

### 5. Colour and composition
- Pick a small palette (three to five colours) with clear value contrast; choose deliberately, or derive it in a perceptual space (OKLCH) for even steps.
- Give the composition a focal area and margins; pure uniform noise across the whole canvas is rarely interesting.
- Vary scale: a few large forms, more medium, many small.
- Use restraint with randomness: constrain it so structure remains visible.

### 6. Iterate by looking
Render a grid of outputs across seeds (e.g. a contact sheet of a dozen thumbnails), look at them, adjust rules or ranges, repeat. Save the good seeds.

### 7. Export
- Raster: render at the target resolution (or use pixel density / a scaled offscreen canvas for print) and save PNG. For print, compute pixels from physical size and DPI.
- Vector: build SVG paths directly or use an SVG export library; optimise path counts for plotters.
- Animation: render frames deterministically from a frame counter and encode with ffmpeg if available.
- Run headless with a browser automation tool to export batches without manual clicks, if one is installed.

### 8. Package
A single self-contained HTML file (inline script, any library vendored locally or loaded from a CDN only if the user is fine with network access) with the config at the top, plus exported images named with their seed and parameters.

## Pitfalls

- Unseeded randomness making a favourite output impossible to recreate.
- Performance collapse from drawing millions of shapes per frame; draw once to an offscreen buffer for static pieces, or move to WebGL.
- Low-resolution export upscaled for print.
- Copying a specific artist's recognisable series; take inspiration from techniques, not signatures.

## Deliver

Lead with the files (sketch and exports) and the seeds used. Describe the concept and the parameters in a few lines so the user can explore. Say which outputs you actually rendered and inspected, and at what resolution.
